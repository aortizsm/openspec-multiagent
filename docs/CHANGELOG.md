# Changelog

Cambios archivados en orden cronológico inverso.

<!-- latest start -->

- **[2026-11-12] test-first-for-observable-behavior** — `@developer` aplica test-first condicional para comportamiento observable y `@test-engineer` complementa la cobertura sin duplicarla; añade una guía detallada en inglés para los nueve agentes y traduce completamente al inglés las specs principales `multiagent-workflow` y `project-documentation`. ([entrada](changes/2026-11-12-test-first-for-observable-behavior.md)) · ([guía](guides/agent-workflow.md))
- **[2026-11-12] consolidate-review-feedback** — Consolida los hallazgos de calidad y verificación en un bundle trazable, con ledger por change y máximo tres rondas; un `FAIL` del verifier tras la tercera se reporta sin otra ronda ni archivo. ([entrada](changes/2026-11-12-consolidate-review-feedback.md)) · ([guía](guides/independent-verification.md))
- **[2026-11-12] sequence-test-engineer-and-remove-resume** — Ejecuta `@test-engineer` antes de las revisiones paralelas y elimina el reinicio por fase; cada reejecución comienza en `@developer`. ([entrada](changes/2026-11-12-sequence-test-engineer-and-remove-resume.md)) · ([guía](guides/independent-verification.md))
- **[2026-11-12] align-workflow-docs-and-specs** — Alinea specs y documentación con el flujo estándar completo, retira `@fast-architect` y explica la eliminación manual de copias ya instaladas. ([entrada](changes/2026-11-12-align-workflow-docs-and-specs.md))
- **[2026-11-09] parallel-orchestrate** — `scripts/orchestrate.mjs` ejecuta `code-reviewer` y `security-reviewer` en paralelo después de `test-engineer` (usando `Promise.all`), manteniendo `developer`, `test-engineer` y `verifier` secuenciales. Si algún revisor falla, se hace rollback y `verifier` no se ejecuta. ([entrada](changes/2026-11-09-parallel-orchestrate.md))

- **[2026-11-04] readme-installation-clarity** — La sección Quick start de `README.md` se reescribe como pasos de instalación numerados y copy-pasteables (Node.js >= 20.19.0, clonar repo, verificar prerrequisitos, inicializar el proyecto de destino), diferenciando claramente "este repo" del "proyecto de destino". Sin cambios de comportamiento ni comandos. ([entrada](changes/2026-11-04-readme-installation-clarity.md))
- **[2026-11-04] add-reinstall-and-reset-commands** — `scripts/reinstall.mjs` y `scripts/reset.mjs` ahora usan los helpers compartidos `removeAgentFiles` y `removeMcpEntries` de `scripts/lib.mjs`, eliminando bloques duplicados; se renombra la variable prohibida `data` a `configData`. Se conservan `--confirm` en reset, `--dry-run` y `mcpNames = ["openspec", "context7", "engram", "codegraph"]`. `npm run reinstall` sobrescribe todos los agentes y reconfigura MCP; `npm run reset --confirm` elimina todo limpiamente. ([entrada](changes/2026-11-04-add-reinstall-and-reset-commands.md))
- **[2026-11-02] change-execution-mode** — El architect puede ejecutar un change en modo `asistido` (por defecto) o `automatico`, elegido por change y registrado en el campo `execution-mode` del `proposal.md`. En modo automático el architect registra la decisión en el completion report. Los valores pasan de inglés a español. ([entrada](changes/2026-11-02-change-execution-mode.md))
- **[2026-11-01] add-codegraph-mandatory-step** — El wizard `npx openspec-multiagent init` ahora instala y cablea CodeGraph como paso 3 obligatorio (sin prompt), al nivel de GitHub y Engram. Si `codegraph` no está en PATH, se instala globalmente vía `npm install -g @colbymchenry/codegraph` y se ejecuta `codegraph install --target=opencode --location=global --yes`. En modo `--dry-run` solo informa sin ejecutar instalaciones reales. Context7 y Engram siguen siendo opcionales. ([entrada](changes/2026-11-01-add-codegraph-mandatory-step.md))
- **[2026-10-29] verifier-spec-compliance** — El `@verifier` ahora revisa que cada requerimiento funcional de la spec esté implementado en el código fuente (spec-compliance review), no solo que los tests pasen. Añade sección `## Spec Compliance` al reporte. ([entrada](changes/2026-10-29-verifier-spec-compliance.md))
- **[2026-10-29] verifier-conflict-resolution** — El `@verifier` tiene una regla de escalación: desacuerdos con @architect sobre estados de requerimiento (`implementado` / `parcialmente implementado` / `no implementado`) se resuelven por @architect con la última palabra. ([entrada](changes/2026-10-29-verifier-conflict-resolution.md))
- **[2026-10-27] auto-rollback** — Automatic git checkpoint before each pipeline phase with rollback on failure. ([entrada](changes/2026-10-27-auto-rollback.md))
- **[2026-10-27] context-bundle** — Nuevo script `scripts/context-bundle.mjs` que genera un único bundle Markdown (propuesta, diseño, tareas, spec y `git diff`) de un cambio OpenSpec para entrega de contexto entre agentes; falla rápido (exit 1) si el cambio no existe. Añade los comandos npm `context-bundle` y `context`. ([entrada](changes/2026-10-27-context-bundle.md))
- **[2026-10-27] infra-stability** — El asistente de setup ya no se cuelga en entornos no-TTY o con stdin pipeado; añade `readInput()` primitiva unificada y hace que `ask`/`askText`/`askYesNo` deleguen en ella. ([entrada](changes/2026-10-27-infra-stability.md))
- **[2026-10-26] remove-zen-model-selection** — Elimina la selección de modelos Zen (OpenCode Go) de `npm run setup`: el asistente pasa de 10 a 9 pasos, ya no hay selector interactivo de modelos ni configuración automática del proveedor `opencode-go`. ([entrada](changes/2026-10-26-remove-zen-model-selection.md))
- **[2026-10-25] add-security-criteria** — Criterios de seguridad objetivos (12 reglas verificables) y agente `@security-reviewer` como gate obligatorio en el loop. ([entrada](changes/2026-10-25-add-security-criteria.md))
- **[2026-10-24] add-human-documentation** — Estructura de documentación humana: carpeta `docs/` con CHANGELOG, entradas por change archivado y guías por capacidad. Reglas de idioma (español en docs/, inglés en specs), fuentes de derivación y gate de documentación antes de archivar.
- **[2026-10-24] add-verifier-agent** — Nuevo agente de verificación independiente. Ejecuta los comandos reales del proyecto y devuelve un veredicto por escenario de la spec. ([entrada](changes/2026-10-24-add-verifier-agent.md)) · ([guía](guides/independent-verification.md))
- **[2026-10-24] harden-multiagent-workflow** — Gates de aprobación con menú, contrato de resultado, severidades de review, permisos de shell por segmento y nombres canónicos de herramientas. ([entrada](changes/2026-10-24-harden-multiagent-workflow.md))
